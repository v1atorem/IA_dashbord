# Invictus Dashboard 2

Сервис аналитики лидов и продаж Invictus: тянет данные из **amoCRM** и **Facebook**,
собирает единую базу лидов (`MASTER_LEADS`) и показывает сводки по **любому диапазону дат**.

## Главная идея — один лид, два направления

Каждая строка базы — один лид. У него разделены:

- **Рекламное направление** — откуда пришёл (по UTM + ручному справочнику кампаний).
  **Расход всегда остаётся здесь.**
- **Фактическое направление продажи** — что реально купил (по полю «Курс» + «Город?»).

Meta — источник истины по расходам, amoCRM — по лидам/квалам/продажам/выручке,
UTM — связующий ключ (`utm_medium`=кампания, `utm_campaign`=группа, `utm_content`=объявление).

Дашборд показывает:

1. **Маркетинг** — по рекламным направлениям: лиды, квал, %квала, продажи, выручка, расход, CPL, CPQL, ROMI.
2. **Продукт** — по фактическим направлениям: продажи и выручка.
3. **Матрицу «реклама → факт»** — сколько лидов из рекламы ТЗ купили ТЗ, а сколько ушли в ГП и т.д. (штуки и выручка).
4. **Каналы** (utm_source).

Мультигородние группы: расход делится между городами **пропорционально числу лидов** в amo
(с ограничением по списку разрешённых городов группы).

## Стек

- **Next.js 14** (фронт + API в одном проекте)
- **PostgreSQL** + **Prisma** (хранилище; синк из API по кнопке и по расписанию)
- Вход по одному паролю (cookie-сессия)

## Быстрый старт (локально)

```bash
npm install
cp .env.example .env      # заполни значения (см. ниже)
npm run db:push           # создаст таблицы в твоей Postgres
npm run db:seed           # настройки + стартовый справочник кампаний/курсов
npm run dev               # http://localhost:3000
```

## Переменные окружения (.env)

| Переменная | Что это |
|---|---|
| `DATABASE_URL` | строка подключения Postgres (Supabase/Railway/Neon) |
| `APP_PASSWORD` | пароль для входа на сайт |
| `AUTH_SECRET` | секрет подписи сессии (`openssl rand -base64 32`) |
| `USD_TO_KZT` | курс для расхода Meta (по умолчанию 465; можно менять в UI) |
| `AMO_SUBDOMAIN` | поддомен amo (`invictusacademy2021`) |
| `AMO_ACCESS_TOKEN` | долгоживущий токен интеграции amoCRM |
| `AMO_PIPELINE_ID` | ID воронки (`7857790`) |
| `FB_ACCESS_TOKEN` | токен Facebook с правом `ads_read` |
| `FB_AD_ACCOUNT_IDS` | ID реклам. аккаунтов через запятую, с `act_` |
| `FB_API_VERSION` | версия Graph API (напр. `v21.0`) |
| `CRON_SECRET` | (необяз.) защита планового синка |

### Где взять ключи

**amoCRM (токен):** Настройки → Интеграции → создать интеграцию → выдать права на сделки →
получить **долгоживущий токен доступа**. Поддомен — из адреса `https://<поддомен>.amocrm.ru`.
ID воронки — в адресе страницы воронки или через `/api/v4/leads/pipelines`.

**Facebook:** нужен токен с правом `ads_read` (System User в Business Manager — самый стабильный
вариант, токен не протухает). ID рекламных аккаунтов — в Ads Manager (формат `act_123...`).
Если аккаунтов несколько — перечисли через запятую.

> Поля amo (`utm_*`, `Курс`, `Город?`, `FORMNAME`) сервис находит по **имени** поля —
> ID полей знать не нужно. Если у поля другое имя — допиши его в `src/lib/config.ts → AMO_FIELD_NAMES`.

## Деплой (рекомендуемо: Vercel + управляемая Postgres)

1. Залей репозиторий в GitHub, импортируй проект в **Vercel**.
2. Заведи Postgres (Supabase / Neon / Vercel Postgres), вставь `DATABASE_URL` и остальные env в Vercel.
3. Первый раз применить схему: локально `npm run db:push` (или из CI) на ту же базу, затем `npm run db:seed`.
4. Плановая синхронизация уже настроена в `vercel.json` (каждые 3 часа, `/api/cron-sync`).
   Задай `CRON_SECRET` в env — Vercel сам подставит его в заголовок.

Подойдёт и Railway/Render — любой хостинг Node + Postgres.

## Как пользоваться

1. Войти по паролю.
2. **Справочники** → разметить кампании: каждой кампании/группе выбрать направление и город
   (или «мультигород» + список разрешённых городов). Там же — правила «Курс → направление» и настройки
   (курс, что считать квалом/продажей).
3. **Сводка** → выбрать даты → **Синхронизировать amo+FB** (тянет свежие данные в базу) → смотреть отчёт.

## Проверка на существующих выгрузках (без API)

Чтобы сверить цифры сразу:

```bash
# залить выгрузки в базу
npm run import:csv -- --amo /путь/amocrm_export.csv --fb /путь/fb_export.xlsx
# или быстрая проверка ядра без БД:
npm run validate -- --amo /путь/amocrm_export.csv --fb /путь/fb_export.xlsx --rate 465
```

> Проверено: расход Meta ($16 818,91 × 465 = **7 820 793 ₸**) сходится до рубля, при разнесении
> по городам/каналам деньги не теряются. Цифры amo зависят от даты выгрузки (стадии сделок дозревают).

## Правила расчёта (можно менять в UI)

- **Квал** — стадия сделки из настраиваемого списка (по умолчанию — как в твоей таблице).
- **Продажа** — стадия «Успешно реализовано» или «предоплата / траншевая оплата».
- **Выручка** — поле «Бюджет ₸» сделки.
- **Расход** — Meta (USD × курс), разнесён по направлениям; мультигород — пропорционально лидам.
- **CPL** = расход/лиды, **CPQL** = расход/квал, **ROMI** = (выручка − расход)/расход.
- Период фильтрует лиды/квал/продажи по **дате создания сделки**, расход — по дню откруток.

## Структура

```
src/lib/aggregate.ts      ядро: MASTER_LEADS, сводки, матрица, разнесение расхода
src/lib/amo.ts            клиент amoCRM API v4
src/lib/facebook.ts       клиент Facebook Marketing API
src/lib/sync.ts           синк в БД + сбор отчёта
src/app/                  UI (сводка, справочники, вход) и API-роуты
scripts/                  импорт выгрузок и проверка ядра
```
